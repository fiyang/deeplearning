# 加入用户属性、电影属性和历史行为

> 历史实验记录：代码于 2026-10-22 与远端核对归档；下文成绩和运行状态仍来自此前实验，本次没有复训。数据、图表与模型产物不随 Git 分发。

这版使用 MovieLens-1M 官方数据中已有的属性，并从过去评分构造行为特征。用户与电影 ID embedding 仍然联合训练；网络仍只有一个 64 维隐藏层。

## 实际输入

| 特征 | 编码与含义 | 输入维度 |
|---|---|---:|
| 用户 ID | 可训练 embedding | 64 |
| 电影 ID | 可训练 embedding | 64 |
| 用户性别 | 类别 embedding | 4 |
| 用户年龄段 | 7 个年龄段的类别 embedding，不是精确年龄 | 8 |
| 用户职业 | 21 个职业类别的 embedding | 8 |
| 电影类型 | 18 维 multi-hot，一部电影可以属于多个类型 | 18 |
| 电影发行年份 | 从标题末尾提取，按训练电影的均值和标准差归一化 | 1 |
| 最近高评分电影 | 最近最多 20 部历史评分 ≥4 的电影，共享电影 embedding 后求平均 | 64 |
| 用户历史评分数、历史高评分率 | 数量取 `log1p(count)/10`；比例用 `(positive+1)/(count+2)` 平滑 | 2 |
| 电影历史评分数、历史高评分率 | 与用户统计相同，只统计过去记录 | 2 |
| 用户喜欢的电影类型 | 历史高评分电影的 18 维类型指示量均值 | 18 |
| **合计** | **拼接后进入前馈网络** | **253** |

```text
用户/电影 ID embedding + 用户属性 + 电影属性 + 历史行为
                            ↓
                       拼接 253 维
                            ↓
                    Linear(253, 64) + ReLU
                            ↓
                    Linear(64, 1) + Sigmoid
                            ↓
                   高评分倾向分数，供候选排序
```

完整模型有 **560,893 个参数**。本轮没有使用邮编和电影标题文本；标题只用于提取发行年份、显示电影名称。评分生成监督标签，时间用于划分数据和确定历史先后，都不直接作为当前样本的答案输入。

这些是评分记录产生的历史偏好，没有点击、曝光、搜索词或播放时长。人口属性是数据提供时的静态快照，不是随时间更新的画像。

## 历史特征怎样防止泄漏

训练样本只使用严格早于当前时间戳的训练记录。先为同一时间戳的全部样本生成特征，再统一更新历史；同一秒的其他评分也不会进入当前特征。历史电影超过 20 部时保留最近 20 部；同一秒的历史电影按 ID 确定稳定顺序。

验证集和测试集使用固定在训练截止时刻的历史快照，不把验证或测试中的评分反馈回特征。这同时保证同一用户的候选电影使用同一份用户历史进行排序。历史不足时只对实际存在的电影求平均；没有历史时历史向量为零，高评分率先验为 0.5。

`test_features.py` 用手算例子检查历史统计、同时间戳隔离、修改当前/未来评分不改变早期特征、输入行顺序不改变结果、验证/测试历史快照不变、各 embedding 梯度以及 checkpoint 独立加载后的推理一致性。

## 三组对照设置

| 模式 | 特征 | 输入宽度 | 参数量 |
|---|---|---:|---:|
| `id` | 用户 ID、电影 ID | 128 | 552,641 |
| `metadata` | ID + 用户性别/年龄段/职业 + 电影类型/年份 | 167 | 555,389 |
| `history` | metadata + 上述历史行为特征 | 253 | 560,893 |

三组均从头训练，完全复用第一轮保存的样本划分和 ID 词表：训练 700,144 条、验证 35,124 条、测试 75,930 条。样本划分归档 SHA-256：`c3d2029812360098cac14a9b906303bd592b209844de57eebd863a8bd05aed9a`。

统一配置：Embedding 64 维，隐藏层 64 维，AdamW，学习率 0.001，weight decay 0.0001，batch size 4,096，梯度裁剪 5，seed 42。各轮训练样本顺序相同，并使用独立于模型初始化的随机数生成器。

最多训练 50 轮，按验证集 **NDCG@10** 保存最佳 checkpoint，patience=10、min_delta=0.0001。三组模型都选定后，再分别评估一次测试集。早停指标、等待轮数和训练批次顺序与最初的 AUC 实验不同，因此判断特征增益应比较本次三组对照。

评估范围仍是已知用户、已知电影；NDCG@10 在每个用户实际评分的候选电影中计算，只统计同时有高分与低分电影的用户。测试排序指标覆盖 859 名用户，候选数中位数 45。该结果不代表全量电影库推荐、真实点击率或冷启动效果。测试集此前用于过第一轮实验，本次是同一数据上的探索性对照；单个种子也不能证明稳定的提升。

## 实际结果

三组训练和评估已完成，整个流程约 **109 秒**。下表全部来自同一次对照实验，测试样本完全一致。

| 特征组合 | 最佳轮 / 实际训练轮 | 验证 NDCG@10 | 测试 NDCG@10 ↑ | 测试 AUC ↑ | 测试 Log loss ↓ |
|---|---:|---:|---:|---:|---:|
| 仅 ID | 18 / 28 | 0.85187 | 0.82250 | 0.76138 | 0.61348 |
| ID + 用户/电影属性 | 19 / 29 | 0.85118 | 0.82976 | **0.76700** | 0.61232 |
| ID + 属性 + 历史行为 | 14 / 24 | **0.86138** | **0.83203** | 0.76467 | **0.60748** |

历史版相对本次仅 ID 对照，测试 NDCG@10 增加 **0.00953**（相对约 1.16%）。历史版在验证与测试的排序指标上最高，适合作为这次按 NDCG 选模的结果；只加属性的版本测试 AUC 更高。特征增多没有让所有指标同步改善，这次结果也不能单独归因于某一个属性字段。

三组都触发早停，完整特征版在第 24 轮结束，保留第 14 轮模型。第 14 轮以后训练损失仍下降，但验证 NDCG 没有再超过最佳值。

三组各 embedding 的梯度检查、CPU 重载与 GPU 分数对照均通过。进一步核对了本机保存的测试样本 ID、标签顺序与原实验一致，并用自包含推理脚本复现了保存的测试分数。


```bash
cd /root/autodl-tmp/deeplearning-lab/recommendation
/root/miniconda3/bin/python score_features.py \
  --checkpoint /root/autodl-tmp/deeplearning-lab/recommendation/runs/features-20261007-092932/history/best.pt \
  --user-id 1164 \
  --item-ids 2987 715 1249 2996 728 587 589 1 6 3006
```

新版 checkpoint 包含训练 ID 映射、属性表、模型权重；history 模式还包含训练截止时刻的历史快照，因此打分不需要重新读取评分标签。脚本拒绝未知 ID，不自动召回或过滤已看电影。

每组子目录保存 `best.pt`、`metrics.csv`、`config.json`、`summary.json`、`test_predictions.npz` 和两张 64 维 ID embedding 表。**新版打分还需要属性和历史特征，只读取两张 ID 向量表不够。** 请使用 `score_features.py`；旧的 `score.py` 保留给最初仅使用 ID 的实验。

实验根目录保存统一结果 `summary.json`、特征定义 `feature_schema.json`、属性表 `feature_tables.npz`、历史快照 `history_state.npz`、相同的数据划分与 ID 映射，以及本轮代码快照 `source/`。

实现文件：`features.py` 构造属性和历史，`feature_model.py` 定义三个模式和 checkpoint 重载，`train_features.py` 训练与评估，`score_features.py` 推理，`test_features.py` 校验，`start_features.sh` 启动。
